# Friction log — Ambient Frames on Vega (submitted with the Devpost entry, 10% bonus)

Format: date (UTC) · where · what blocked us · what we did · suggestion to Amazon.

- **2026-09-05 · docs** — `developer.amazon.com/docs/vega/0.21/vega-sdk-setup.html` and `.../vega-sdk-install.html` (linked from search) return 404; the live page is `vega/0.23/install-vega-sdk.html`. Suggest redirects from older version paths.
- **2026-09-05 · install** — `get_vvm.sh` exits with "jq is required" on a stock Ubuntu 24.04 WSL2 without sudo. Installed a static `jq` binary into `~/.local/bin`. Suggest the installer download jq itself, as it already does for the SDK.
- **2026-09-05 · install** — in a non-interactive shell (ssh + nohup) the installer prints `read: /dev/tty: No such device` for the "Install Vega SDK version X? [Y/n]" prompt, then proceeds with the default. Works, but a documented `--yes` flag would make CI/remote installs less alarming.
- **2026-09-05 · media API** — `react-native-w3cmedia` documents `loop`, `volume`, `muted` as unsupported on `HTMLMediaElement`. For an ambient app that means pre-mixing audio at render time and restarting on `ended`. Suggest at least `loop` (gapless restart is hard to do from JS).
- **2026-09-05 · VVD** — documentation states the Vega Virtual Device does not support WebView on Ubuntu (only Apple Silicon Mac or a Fire TV 4K Select). Web-tech entrants on Linux therefore cannot produce the required simulator demo; worth stating on the hackathon page.
- **2026-09-05 · VVD** — no documented screenshot/recording command for the virtual device; demo capture must be done host-side.
- **2026-09-05 · VVD** — with `/dev/kvm` unreadable the CLI silently falls back to TCG; boot then either times out (150 s) or comes up so slowly that `run-app` fails with `Could not get value for 'com.amazon.devconf/system/device-info/device-type-id'`. A pre-flight "KVM not available, expect very slow boot" warning would save an hour. With KVM: boot < 1 min, install + launch OK.
- **2026-09-05 · CLI** — `vega project generate -o DIR` writes the template into DIR itself rather than DIR/<name>, unlike most scaffolders.
- **2026-09-05 · media API** — nothing in the 0.24 media docs says how to play a **bundled** file. `asset://` and `require()` fail; the working form is `/pkg/assets/raw/<file>.mp4`, found only in a community Q&A. One line in `media-player` ("local assets: `/pkg/assets/raw/…`") would save every offline-content app a search.
- **2026-09-05 · media API** — `HTMLMediaElement.loop` is documented as unsupported, yet `react-native-w3cmedia@2.3.4-rn-83` implements it in JS (`MediaPlayer.js`: on `ended` with `loop_` it calls `play()` and swallows the `ended` event). Either document it as supported (with the swallowed-event caveat) or remove it — apps that rely on `ended` for their own scheduling get silently starved when `loop` is on.
- **2026-09-05 · VVD** — remote-control injection exists (`vega device run-cmd -c 'inputd-cli button_press KEY_RIGHT'`, also `series`, `send_text`) but is undocumented; found by listing `/usr/bin` on the device. It is exactly what CI / headless UI checks need — please document `inputd-cli`.
- **2026-09-05 · CLI** — `vega device is-app-running` prints the help text instead of the result when the app id is given positionally; the flag form is not obvious from `--help` examples (which use a placeholder serial).
- **2026-09-05 · build** — the eslint kepler plugin warns on every import of a system-distributed library (`react-native-kepler`, `react-native-w3cmedia`) with a 3-line message; a one-time notice or a documented off-switch in the template `.eslintrc` would keep lint output readable.
- **2026-09-05 · content** — because `HTMLMediaElement.loop` is unreliable and `volume`/`muted` are absent, an ambient app has to ship fully pre-rendered A/V and keep it small: we ended at 10-min loops, ~40 MB per mood (≈ 200 MB bundled). Nothing in the docs states a `.vpkg` size limit or an install-size budget for the VVD / Fire TV devices; a documented ceiling (and whether large assets should go through the expansion-file/OTA path) would decide the loop length up front.
- **2026-09-05 · docs** — no guidance on video encoding profiles the Vega media stack accepts (H.264 level/profile, HEVC?, max resolution/fps, AAC-LC vs HE-AAC). We stayed on H.264 High@1080p24 + AAC-LC 96k because that is what the sample used, not because the docs said so.
- **2026-09-05 · CLI** — `vega run-app` failed right after a fresh VVD boot with `Cannot read properties of undefined (reading 'trim')` from its `uninstallApp` pre-step (device log shows `ls: /data/local: No such file or directory`); the explicit `install-app -p … && launch-app -a …` pair worked 30 s later. A clearer error ("app not installed / device still settling") and an install-if-missing path would avoid a confusing first run.
- **2026-09-19 · storage** — the AsyncStorage page lists the package and its `package.json` lines but says nothing about `manifest.toml`. With `@amazon-devices/react-native-async-storage__async-storage@2.1.9000000000-rn-83` no `[[needs.module]]` entry is needed: the log shows `Successfully linked 'RNCAsyncStorage' from OS metadata`. We only learned that by installing it. Suggestion: one line per system library stating "no manifest entry needed" (or the exact entry), since `react-native-w3cmedia` does need four.
- **2026-09-19 · build** — every build prints `ERROR · Validation errors found while scanning node_modules … version 2.3.4-rn-83 is not part of its kepler-compatibility.json` for Amazon's own `-rn-83` packages (w3cmedia, async-storage), then builds fine. An ERROR banner that is not an error trains people to ignore real ones. Suggestion: add the `-rn-83` versions to those packages' compatibility files, or downgrade the message to a warning.
- **2026-09-19 · build** — a Debug build fails with `Unable to resolve module @babel/runtime/helpers/interopRequireDefault from ../engine/scheduler.ts` when shared code lives outside the app folder (Metro `watchFolders`); Release builds of the same code passed. Fix = `resolver.nodeModulesPaths: [path.join(__dirname, 'node_modules')]` in `metro.config.js`. Suggestion: generate that line in the template, since monorepo-style layouts are common.
- **2026-09-19 · VVD** — `vega virtual-device start` over ssh waits 60 s and reports "virtual device unresponsive" with QEMU already gone, no reason given. Cause: `DISPLAY`/`WAYLAND_DISPLAY` unset in the ssh session (WSLg). Exporting `DISPLAY=:0 WAYLAND_DISPLAY=wayland-0 XDG_RUNTIME_DIR=/mnt/wslg/runtime-dir` fixes it. Suggestion: fail fast with "no display available".
- **2026-09-19 · input** — on the VVD the remote's centre button arrives as `KEY_ENTER` (`eventType: 'enter'`) and is delivered to the focused `Pressable`'s `onPress`, not to `useTVEventHandler`; `inputd-cli button_press KEY_SELECT` is accepted but produces no event at all. The TV-input docs talk about `select`. Suggestion: document which key codes the VVD maps to the remote's buttons.
